# 任务提示词生成器

把材料变成能独立执行的任务。目标、输入、交付和验收必须具体，方案与工具选择留给执行者。

## 先确定输入边界

- 使用用户提供或授权读取的材料；不猜测另一个工作区的路径。
- 不读取候选模型身份、既有得分或历史回答来反向出题。追加任务先由上游复盘，将中性的业务需求交给本 Skill。
- 材料缺少目标、关键输入或授权时，只追问会改变任务成立条件的缺口。非关键细节标明假设后继续。
- 正式任务保留真实业务闭环；教学用虚构场景必须明确标注，不冒充真实项目或已发生的运行。

## 执行顺序

读取材料并分层 → 判断是否适合出题 → 脱敏 → 校准粒度 → 生成任务包 → 检查可执行性和发布边界。

完整任务包包含 `prompt.md`、`design_notes.md`、`desensitization_log.md`、`acceptance_checklist.md` 和 `risks_and_gaps.md`。只有 `prompt.md` 与必要脱敏输入交给执行者。其他文件留在内部；真实值与代号的映射不得公开发布。

无法成立时输出 `rejection.md`，说明具体缺口和最小补充材料，不编造输入。只生成提示词时，不擅自开始运行和评分。

## 不可省略的检查

1. 同一对比任务使用逐字一致的提示词和必要输入，除非明确比较不同条件。
2. 提示词写业务需求，不写工具调用配额、内部评分规则、标准答案或自评分数要求。
3. 工具调用量只是条件估计，不能代替难度、工作量或完成质量，也不能承诺未实跑的最低次数。
4. 脱敏要保留决策难点，检查可组合反推的背景、精确数字、时间、编号与案例。
5. 阶段性产物尽早落盘，失败时保留已完成部分和明确缺口，不把文件存在当作验收完成。

从本 Skill 目录执行：`python scripts/validate_distilled_task.py <任务包目录> --json`。
脚本只能检查结构与部分文本风险；人工仍需核对业务闭环、隐私组合和实现自由度。
