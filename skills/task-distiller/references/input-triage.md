# 信息分层与提问规则

本规则决定：原始材料里哪些是硬约束、哪些可推断、哪些必须追问、哪些直接丢弃。
目标是**不因材料不完美就反复追问**，但也不把关键缺口悄悄假设掉。

## 四层分类

| 层 | 含义 | 处理方式 |
|---|---|---|
| L1 已知事实与硬约束 | 用户明确陈述的目标、要求、不可改变的边界、授权范围、必须保留的验收条件 | 原样保留，进入提示词的"目标/边界/护栏" |
| L2 可合理推断 | 材料未明说，但从上下文、行业惯例或材料内部一致性可推断 | 采用，但在 `desensitization_log.md` 的"假设"区标注依据 |
| L3 关键缺失 | 会改变任务目标、授权边界、验收标准或隐私风险的信息 | **暂停并向用户提问**；若用户不回答，写入 risks_and_gaps 并考虑拒绝 |
| L4 噪音 | 寒暄、重复、与任务无关的链接、情绪表达、过时背景 | 直接删除，不逐条说明 |

## L3 判定：什么才值得提问

只有缺口会改变以下之一时，才属于 L3：

1. **任务目标**：缺了它不知道要交付什么；
2. **授权边界**：缺了它无法判断能否访问/处理某文件、账号或外发某信息；
3. **验收标准**：缺了它无法判断产物是否合格；
4. **隐私风险**：缺了它无法判断某信息是否可保留或需脱敏；
5. **任务真实性**：缺了它任务退化为虚构演示。

以下情况**不要提问**，按 L2 假设处理并记录：

- 工具的具体版本、目录名、文件名等可用合理默认值替代的细节；
- 用户未指定输出位置（用默认 `distilled_task/`）；
- 业务背景中可从材料推断的常识性上下文；
- 不影响核心闭环的可选增强项。

## 提问方式

- 一次列出所有 L3 缺口，编号、具体、给出可选项或默认假设；
- 不反复盘问：用户回答后即继续，除非回答引入新的 L3；
- 用户明确授权代定时，只有可合理决定的细节转 L2；未知授权、缺失的关键事实和不可验证输入不能因这句话视为已具备；
- 缺少关键答复时，先完成独立部分并列明依赖；不把等待时间当作同意。材料确实无法补齐时，说明暂不适合出题。

## 记录要求

- L1 不单独记录（直接体现在提示词中）；
- L2 每条假设写入 `desensitization_log.md`：假设内容、依据、若错误对任务的影响；
- L3 提问与用户答复写入 `risks_and_gaps.md`；未获答复的列入"不确定项"；
- L4 只做汇总计数或类型说明（如"删除 12 条寒暄与无关链接"），不保留原文。
