# 适用性判断与拒绝规则

不是所有材料都值得或都能转成生产任务。本规则决定"继续出题"还是"拒绝并给最小补充建议"。

## 继续出题的必要条件（全部满足）

1. **真实闭环**：材料对应一件真实做过或真正要做的事，有明确起点和终点；
2. **授权充分**：材料归属使用者，或使用者有权处理；不涉及未授权的他人隐私或客户数据；
3. **可验收产物**：任务结果可以被打开、运行、重新计算或人工核查，而不是只"谈一谈"；
4. **必要材料可得**：完成任务所需的输入、规则或样本在脱敏后仍可提供；
5. **有判断空间**：任务包含需要模型做决策的部分，而不是纯照抄或纯体力；
6. **可安全脱敏**：难点和验收条件不绑定在不可外发的秘密上。

## 必须拒绝出题的情形

- 材料要求使用真实凭据、生产环境写权限或真实客户数据，且无法用虚构等价物替代；
- 核心难点本身就是不可外发的专有信息，脱敏后任务不成立；
- 材料只是一个想法/愿望，没有任何可执行的输入或闭环（属于 L3 关键缺失且无法补充）；
- 用户要求按特定模型定制、或要求根据已有分数反向出题（违反公平性）；
- 任务要求伪造数据、伪造轨迹、误导他人或违反法律法规。

## 可以出题但要降级处理的情形

- 材料敏感但核心难点可泛化：用虚构等价数据替代，在记录中说明；
- 部分输入缺失但不影响核心闭环：按 L2 假设并记录，在 risks_and_gaps 中列出；
- 旧提示词过宽/过死：重磨粒度后产出，并在 design_notes 中说明改了什么、为什么。

## 拒绝时的输出格式

写 `rejection.md`，包含：

```markdown
# 不建议直接出题

## 结论
<一句话说明为什么当前材料不能转成生产任务>

## 属于哪类不足
- [ ] 真实闭环不足
- [ ] 授权不足
- [ ] 缺少可验收产物
- [ ] 必要材料缺失
- [ ] 缺少判断空间
- [ ] 无法安全脱敏
- [ ] 其他：___

## 最小补充建议
1. <具体、可操作的补全项；说明补什么、补到什么程度>
2. ...

## 补全后如何重新触发
<把补充材料提供给 task-distiller 即可重新提纯>
```

拒绝要**具体**：不说"材料不足"，而说"缺少可用于核对的输入样本和判断口径，提供一份脱敏后的样例数据和核对规则即可继续"。
