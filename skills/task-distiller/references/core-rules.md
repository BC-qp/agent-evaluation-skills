# 基本规则与工作流

1. **真实闭环**：任务必须来自真实工作，有真实目标、真实输入、可交付产物和可核查方法；不虚构复杂场景。
2. **统一提示词**：除非用户明确要求比较不同条件，否则同一任务对所有执行者使用**逐字一致**的提示词和输入；一致性由任务组织者在外部保证，不写进 `prompt.md`。
3. **中间粒度**：写死目标、边界、必要输入、交付物和验收条件；把方案选择、信息组织、工具组合、异常处理和质量取舍留给执行模型。不提供逐步标准答案、唯一工具链或隐藏解法。
4. **不制造伪区分度**：不靠冷知识、提示注入、文字陷阱或纯粹堆工作量制造模型差距。难点必须来自业务本身。
5. **最小提问**：只在缺失信息会改变任务目标、授权边界、验收标准或隐私风险时才追问；其余做**有标记的合理假设**并继续。
6. **脱敏不删难点**：替换人名、组织、账号、链接、路径、时间、专有数据时，保留业务逻辑、决策难点和验收条件；替换前后一致。
7. **可回滚的判断**：对保留、泛化、替换、删除所作的关键判断留下简短记录，便于复核。

## 提纯工作流

按顺序执行，并尽早落盘阶段性产物：

1. **通读与建档**：读取用户提供的全部文本和文件，记录材料清单和来源类型。不要假设能访问材料之外的路径。
2. **信息分层**：按 [信息分层](input-triage.md) 标记 L1–L4，列出 L3 缺失项。若存在 L3 缺口，提问；否则继续。
3. **判断是否值得出题**：按 `suitability.md` 评估真实闭环、授权、可验收产物和必要材料是否充分。不充分时产出"拒绝结论 + 最小补充建议"，不要强行包装。
4. **脱敏与泛化**：按 `privacy.md` 处理人物组织、账号凭据、内部链接路径、来源时间标识、专有数据、客户信息和可组合反推的细节；记录每处关键处理。
5. **设计任务**：确定目标、上下文、输入、执行过程观察点、交付物、验收边界、护栏和失败处理。用 `task-granularity.md` 自检粒度。
6. **产出文件**：按 [输出合同](output-contract.md)写文件。`prompt.md` 必须可原样交给任何执行者，且不得暴露模型对比、评分或题目设计信息。
7. **自检**：按主入口的不可省略检查逐项核对；不通过先修正再交付。
