# 脱敏处理规则

目标：在**保留真实业务逻辑、决策难点和验收条件**的前提下，让材料可以安全外发给待测模型或放入可分享的任务包。

## 必须处理的类别

| 类别 | 典型内容 | 处理方式 |
|---|---|---|
| 人物身份 | 真实姓名、昵称、工号、邮箱、手机号、签名 | 角色化替换（"申请人""审核人B""客户方对接人"），全文一致 |
| 组织身份 | 公司名、团队名、客户名、供应商名、内网主机名 | 中性代号（"组织A""客户方""上游服务X"），保持业务关系 |
| 账号与凭据 | 账号、密码、API Key、Token、Cookie、验证码、私钥、连接串 | **一律删除**；需要"有权限访问"这一条件时只描述权限，不给凭据 |
| 内部链接与路径 | 内网域名、工单号 URL、云控制台链接、个人用户目录、盘符、UNC 路径 | 替换为相对路径或功能描述（"内部工单系统""项目根目录下的 data/"） |
| 来源与时间标识 | 提交哈希、工单号、精确时间戳、可定位的日期组合、版本号组合 | 泛化为相对时间或顺序标识（"第一天""提交 N-2"），保留先后关系 |
| 专有数据 | 真实业务数值、财务数据、客户清单、未公开指标 | 用结构相同、数值虚构但合理的数据替代；保留字段、依赖关系和计算/判断难度 |
| 客户信息 | 客户名单、合同细节、联系人、交易记录 | 删除或抽象；任务不需要就不要保留 |
| 组合反推细节 | 单条不敏感但多条组合可锁定真实对象（城市+岗位+时间+小团队规模） | 至少再泛化一层，直到无法稳定反推 |

## 三条不能违反的约束

1. **不能把难点一起删掉**。例如材料的核心是"根据某内部数据口径核对金额"，脱敏后仍要保留"按指定口径核对"这一动作和难度，只把口径名称和数值替换成虚构但等价的。
2. **替换前后一致**。同一个人/系统/字段在提示词、输入材料、验收标准里必须用同一个代号；建议维护一张替换映射表。
3. **删比硬留安全**。无法安全脱敏、又不是任务必要条件的内容直接删除；无法安全脱敏但又是任务核心的，按"拒绝出题"处理（见 [适用性判断](suitability.md)）。

## 脱敏与假设记录格式

在 `desensitization_log.md` 中记录，建议用表格：

```markdown
## 替换映射
| 原类型 | 来源类别（不含原值） | 替换为 | 出现位置 |
|---|---|---|---|
| 人名 | 姓名字段 | 审核人B | 背景、输入第2段 |
| 内部系统 | 内部链接字段 | 内部工单系统(链接略) | 背景 |

## 删除项
- 删除真实 API Key 一处（任务不依赖真实凭据）。
- 删除客户名单 3 条（与任务目标无关）。

## 泛化项
- 精确日期 泛化为"上线前一周"，保留先后顺序。

## 假设（L2）
- 假设该数据导出为 CSV 格式；依据：用户提到"表格"。若实际为 JSON，输入读取步骤需调整，不影响验收逻辑。

## 保留判断
- 保留"按账龄分三档计提"的业务规则，因为它是核心判断难点，不含可识别信息。
```

## 脱敏后复核

- 通读替换后的提示词，确认代号无歧义、关系正确；
- 用 `python scripts/validate_distilled_task.py <任务包目录>`（从 Skill 根目录执行） 扫描密钥模式和个人绝对路径；
- 人工检查：是否还能从多个细节组合反推真实人物或组织？是否残留链接参数、盘符、用户名？

## 公开分享边界

脱敏记录本身也可能泄露身份。共享版本只记录信息类别、替换规则和假设，不保留原值或可反查映射。不得发布真实会话ID、运行编号、文件哈希、精确时间组合及私有来源目录。案例无法确认公开许可或仍可反推来源时，删除或整体重写成明确标注的虚构教学示例。替换后的示例数字不称为实测。
