# 工具调用量与任务难度、工作量的映射方法

## 结论与用途
工具调用量是任务、执行策略、工具封装、已有资产、验收深度和环境共同作用的结果。它能帮助预估执行规模、发现任务被压缩的位置；单独一个调用数不能反推出任务难度、工作量或完成质量。当前方法是基于真实轨迹的结构化估计框架，尚不是经过独立样本验证的预测模型。
用于任务设计、补轮设计及运行复盘。先分析任务需要哪些真实业务闭环，再估计在特定执行环境和模型已观察行为下可能发生的工具动作；运行后根据实际完成深度更新映射。内部目标数字不写入执行提示词，不通过强制拆工具、无效重复或禁止合理自动化制造调用量。

## 一、先分清四个量
| 量 | 判断依据 | 不可替代的概念 |
|---|---|---|
| 任务难度 | 决策不确定性、算法与空间约束、跨模块一致性、错误定位及恢复难点 | 不等于提示词长度、模块数或调用数 |
| 工作量级 | 必须完成的范围、独立修改与验收对象、状态变化和交付覆盖 | 不等于文件数或自动生成的用例数 |
| 执行调用量 | 指定口径下实际发出的工具动作，包括读取、实现、观察、修复和交付 | 不等于脚本内部循环、工具执行时间或全部推理工作 |
| 完成深度 | 真实业务是否可操作，边界、恢复与联动是否通过核查 | 不等于任务列表completed或工具返回成功 |

同样工作量可因自动化和复用减少调用；高难算法也可能主要在一次推理后生成。大量调用可能来自环境失败，而低调用可能来自高效实现或未完成要求。必须结合轨迹与结果区分，不能预先认定低调用就是题目简单或模型偷工。

## 二、固定统计口径与证据身份
1、明确目标是新增还是累计、平台工具回合还是原生工具调用。一个Agent回合可能同时发起多个工具；一次Bash也可能完成许多业务动作。两类合并分别记录。
2、按调用ID配对参数和返回，去重复制上下文，沿明确续接及子Agent引用还原范围。保留提示词、输入、模型运行、Session、时间边界和哈希；无法还原则标明缺口。
3、分开原模型执行、模型自行生成的测试或模拟、评审者本机复核。原始压缩包不改；测试通过只有在覆盖需求且观察可信时才支持完成判断。

## 三、从需求到动作的映射表
| 需求形态 | 可能的执行方式 | 易被压缩的部分 | 应检查的真实深度 |
|---|---|---|---|
| 改字段、顺序、批量素材 | 一次转换脚本生成多份结果 | 数据量、文件数 | 内容是否实际生效，身份及引用是否一致 |
| 增加模块或界面 | 一次写入完整文件或批量脚手架 | 函数、按钮、模块数量 | 模块是否接入实际页面，完整用户流程能否完成 |
| 多场景测试或截图 | 通用脚本一次循环执行 | 案例、视口、截图数量 | 断言是否观察正确业务，是否掩盖缺对象或错站 |
| 状态编辑影响派生结果 | 修改、运行、观察、定位、再修改 | 共享检查框架仍可复用 | 原始状态、派生结果和用户界面是否一致联动 |
| 竞争、取消、事务与恢复 | 构造可控顺序，经真实入口操作并检查持久状态 | 内存模拟和预填版本很便宜 | 晚到结果、跨窗口冲突、中断后重开是否真实正确 |
| 构建、发布与挂载 | 脚本生成产物、清单及归档 | 文件清单、哈希、报告可批处理 | 当前编辑是否进入实际发布，失败切换和回退是否同版 |
| 环境排障 | 重试、改路径、安装及兼容修复 | 与任务本身不一定有关 | 单列已观察开销，不把偶发故障当未来最低调用保证 |

使用时把任务拆成可以验收的业务闭环，标出输入、状态变化、依赖、可观察结果和当前已有资产。不要将表中类别数变成每题固定配额，也不要按每条需求分配固定调用数。

## 四、建立估计并检查能否被批处理压缩
内部估计可写为：新增工具回合≈接管与复现＋必要实现及真实反馈工作包−共享准备、复用与批量执行。已经直接估平台回合时，不再套一次原生调用到回合的系数。
每个工作包记录依据、可复用部分、实现缺口、需要实际观察才能决定的部分，以及保守/常规/充分执行的假设。观察到的同类片段只能作量级锚点，不能证明另一个工作包必然花相同次数。
用“一次批读、通用生成器、共享测试和一次打包”尝试压缩整个任务。能压缩的工作如实扣除。若剩余难点只是多写报告或多跑样本，应重构需求或补足真实输入，而不是抬高预测。
至少区分“完整完成并验收”和“骨架加浅测提前收尾”两种情景。后者用于识别提示词验收替代风险，不能计为达到目标。明确的验收要求只能降低替代空间，不能保证模型遵循。

## 五、审查预测依据
1、实测值、专家估计与尚未验证的目标分开。人工工作包区间的相加只是情景计算，不是置信区间、达标概率或可靠下界。
2、任务状态、文件存在、接口存在、恒真断言或只检查计数，不足以支持完成。核查工具返回、代码调用链、真实操作及独立观察能否相互对应。
3、调用多不直接加质量分；调用少也不直接扣分。将预测误差、自动化复用、环境成本和需求遗漏分别解释。
4、不拿同一条轨迹既拟合又宣称回测成功，不用其他模型尚未结束的页面计数推断其行为模式。没有独立续轮或任务样本时，只交付初步映射及不确定性。

## 六、运行后更新
发送前冻结预测、提示词、输入及估计假设。拿到真实续段后按用户输入边界统计新增动作，记录完成深度、复用方式、返工及环境影响，再比较预测。目标未达时，先辨认是工作包高估、自动化更强还是要求未完成；不能一律归为任务太简单。
持续积累不同任务、工具封装和实现深度的独立样本，再更新相似工作包范围。不要把单个样本的转换比、模块数量或调用目标固化成通用系数。

## 输出约定
给任务设计者：结论、统计口径、实测映射表、工作包假设、条件预测、验收替代风险、需实跑验证的部分。给执行者：实际业务需求、输入、操作结果及验收边界，不下发内部次数目标、评分材料或预测表。
教学演示见[虚构案例](synthetic-examples.md)。示例数字仅用于解释计数口径，不是实测，也不能用于预测。

根据轨迹设计追加任务时，先由上游复盘形成中性需求，再按本 Skill 的基本规则提纯。实际提示词优先交付，内部估计不下发。
