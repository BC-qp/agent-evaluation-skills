# 虚构教学案例

以下情境和数字为讲解而构造，不来自真实项目、模型运行或个人经历。

## 基本规则：社区借物登记

原始需求：“把借出记录整理好，知道哪些要追回。”

先确认输入字段、归还判定和交付用途。可形成的任务是：读取一份虚构借物表，按提供的到期规则生成待归还清单；同一物品的重复编号、已归还记录和缺失日期需要分别处理；交付可复核表格及异常说明。

必须给出规则与样例数据。留给执行者的是数据读取、异常处理方案和输出组织；不能暗中要求提示词没说的提醒发送功能。没有日期规则时列为关键缺口，不能自行认定谁逾期。

## 计数演示：批处理不等于偷工

设一个虚构轨迹有4个带工具动作的回合：第一回合含2次调用，其余回合各1次。因此是4个工具回合、5次原生调用。某一次调用里的脚本处理20条借物记录，不增加为20次原生调用。

这只能解释统计单位，不能说明任务已完成。还要核对重复编号是否按规则处理、缺失日期是否被明确保留，以及最终文件是否可重新打开和计算。

## 从真实需求补深度

若虚构产物只有一份总数表，而任务明确需要逐项待归还清单，追加需求应围绕可核对的条目和异常处理。不要要求增加工具次数、禁止批处理或多输出几份相同报告。

内部估计要分别考虑共享读取、批量生成和真正需要反馈后决定的工作。没有真实后续运行时，只写条件与不确定性，不把这个教学例子当统计样本。
