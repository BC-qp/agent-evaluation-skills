# 输入与证据身份

1. 读取实际发送的提示词、附件、补充输入、任务RUBRIC、最终答复和交付文件。优先核对包内实际输入，例如实际输入文件、消息导出和运行清单；本地待提交稿只能辅助对照。
2. 按模型记录实际发生的轮次。准备好的续轮不算执行过，单纯“继续”是否纳入要看其是否完成原任务。额外提出的新任务不能悄悄混入原任务成绩。
   用户限定只评第一轮时，产物质量、执行过程和反馈都以首轮为界。追加轮覆盖的文件须恢复首轮版本或寻找可靠的首轮证据；无法还原的受影响部分不作评价，不能拿最终目录替代首轮产物。
3. 同题按共同任务目标验收，明确输入或轮次差异。不同模型不必机械截到相同轮数，也不能把额外要求当作其他模型的缺项。
4. 分开标记三类材料：本次被评模型的执行记录、模型交付的教学案例或模拟日志、评审者本机复核记录。教程中的Trace、故障演练和PASS文件不能直接证明被评模型本次如何工作。
5. 缺少完整会话时，检查可追溯的工作区过程材料。记录不完整只限制可评价范围，不自动扣分，也不能补写未见的搜索、重试或自测。若连合理的过程分都无法支持，先列待补材料，不填虚假分数。
6. 压缩包乱码、用户改名导致链接失效、代理忙碌或暂时超时，先定位原因。不能未经核实归为模型错误；若确有恢复失败，再评价其处理和实际影响。
7. 原包保留不动。按需解压选定样本，核对真实输出、文件版本和可用性，不因目录可读或文件名存在就认定交付成功。

### 原始Session的接收与检查

原始JSONL、终端／WebUI完整记录及对应产物可以作为过程材料。优先接收完整JSONL，保留文件名、Session ID、所属任务ID、运行ID和模型名；有多段续接或子Agent记录时，一并确认它们与主会话的关系。按实际运行器的导出说明核对主会话和子会话，不把一种运行器的索引格式套到另一种。

“错误”筛选页截图可定位失败事件，但不能独立证明整体过程质量。需要回看失败前输入、工具返回、后续修复、是否重试成功和最后交接，区分一次合理试错、反复无效尝试和未解决问题。不能按错误条数直接扣分。保留成功步骤和恢复结果，避免只截负面片段。

Session可能刷新延迟，导出时检查是否包含最后一轮及最终交付；与终端／WebUI、文件版本交叉核对。某个模型的记录不能拿来评价另一个模型。完整日志供内部核查，提交只选相关证据，避免暴露无关账号信息或凭证。
