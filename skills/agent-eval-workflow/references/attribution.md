# 行为归因与标签

每次评测先读取实际页面的选项及其定义，逐字使用本栏标签，不沿用旧标签清单、不自造名称、不拆开一个完整选项。无准确标签时不勉强勾选，稿内可写“无”，具体事实照实写入备注。以下示例只在本次评测存在对应标签时使用。

### 执行过程：先判断具体行为，再匹配标签

完整Session已提供时，必须用它扩展过程验收深度，覆盖需求理解、输入与Skill读取、计划和实施、工具选择、失败恢复、用户纠偏响应、核验及交接。不能只围绕最后自检寻找问题，也不能把所有过程缺陷都归为“自测不充分”。先定位真实事件和前后文，核对后续是否恢复，再判断行为、影响及责任归属，最后从当前平台选项中匹配标签；不能先选标签再找材料凑证据。

“自测不充分”仍可使用，但必须有检查缺失、检查范围不足、检查方法无效或未复验最终版本的实际依据。仅有最终产物错误，或不完整记录中没看到测试，不能单独支持该标签。问题主要发生在理解、实施、恢复或交互环节时，应优先辨认这些环节的具体行为，不用“最后没有检查出来”覆盖其实际性质。

按当前标签定义核查以下行为证据：

- 重复失败是否来自无效方法，是否确实增加了执行成本。
- 用户已经明确的要求是否被反复忽略；正常澄清和新增要求不算。
- 必须且可访问的材料是否被跳过；不能仅凭缺少某个工具名断言没有阅读。
- 中断是缺输入、环境问题还是已有条件下的无故停止。
- 替代方案是否恢复了原任务要求，并进行了相应复验。
- 面向用户的回复语言是否违背要求；代码、引用和工具输出中的英文不等于回复语言错误。

这些是核验方向，不是预置的平台标签。平台没有准确选项时，在备注中如实说明行为，不硬贴“自测不充分”，不自造标签或跨栏借用标签。多个标签只有在各自有独立依据时才同时选择，同一现象不重复处罚。高分、低分的正文写法仍按既有规则执行。

交付前横向复核各模型的过程备注、标签与Session定位：若大量使用“自测不充分”，必须回查是否漏评了其他阶段、忽略了更准确的标签，或把产物问题直接搬成过程问题。复核后证据确实一致可以继续使用同一标签；不设标签数量、种类或差异配额。多元化来自充分识别真实行为，精准性优先于标签看起来丰富。此项复核在内部完成，不新增报告、模板字段或评分稿栏目。
