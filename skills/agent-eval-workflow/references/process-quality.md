# 过程维度评分

先读取[评分接入](scoring-contract.md)和[证据身份](evidence-identity.md)。

依据实际记录看是否理解任务、读取必要材料、实施有用检查、发现并修正问题、处理失败、保持要求及完成交接。检查命令执行成功，不等于检查覆盖了关键要求；导出成功也不等于完成最终校对。反过来，没有看到某次检查，不等于能断言它没有发生。

高分需要有效核验和可靠推进的实际依据；中段分数解释执行完成但遗留的检查、恢复或交接问题；低分说明反复失误、严重遗漏、停滞等行为及造成的结果。不要把产物分直接映射为过程分。

- 产物质量与执行过程分别确定质量范围，再分别进行同题模型比较。两栏的排序可以不同，不把产物排名直接套到过程。
- 同一问题若同时影响两栏，产物栏写交付损害，过程栏必须另有实际行为或检查覆盖证据，避免重复处罚。
- 有价值的改进应被承认。例如补齐评分分母能降低理解成本，但不能抵消其他缺乏依据的数据或结论。
- 工具次数、耗时、Token、体积不直接代表质量。本次评测若有工具调用门槛，属于任务合规核对，不能按调用数量给质量奖励。
- 同题模型即使都有三处问题，也要比较问题是否触及核心目标、影响多少使用场景、是否会误导结论，以及修复需要改一处说明还是重做关键机制。问题条数相同不代表质量相同。

## 必须覆盖的环节

检查理解需求、读取材料、计划实施、工具选择、失败恢复、响应纠偏、核验最终版本及交接。看见一次报错后，要继续核对后续修复和复验；记录不完整时限制结论范围，不能直接推定未做检查。

先遮去产物分，仅据轨迹确定过程质量范围，再按[横向校准](score-calibration.md)比较。标签按[归因规则](attribution.md)匹配，证据按[取证规则](evidence-capture.md)定位。
