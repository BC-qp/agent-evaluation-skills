# 语言与评分稿说明规范

1. 每个计分维度通常写1至3条编号评价，使用“1、2、3、”，条目间不空行。给分依据独立成句或紧凑一段，可在编号前或后，不塞进某个分论点，不每条重复报分。围绕问题范围、严重程度、剩余可用性和修改成本，或经核验的具体亮点，说明事实为何支持分数；不编造逐项扣分算式。
2. 每条讲具体内容与使用影响，必要时附原句、数值和位置。依据具体事实与等级解释质量，不为了平衡篇幅添加陪衬优点；亮点必须核验，重要缺陷必须说明。若本次表单另有正负反馈要求，按其格式适配。评分仍全面考虑实际表现，不为文风制造缺点或改分。
3. “交付齐全”“有参考价值”“内容丰富”不单独作为亮点；要指出具体实现与实际收益。反馈选择产物质量和执行过程尚未讲过的实际使用发现、受阻点或影响，换个说法重复同一问题也不算新点。确有必要才提出修改建议，不把未执行的测试写成实际体验。
4. 复制框只包含可直接交给项目方的正文。给用户的必要说明统一放稿首“前置说明”，能一句说清就不写两句；没有则省略。不在各模型、维度或截图下新增“提交注意”等栏目，不混入改稿经过、内部安排或待执行事项。只有备注和反馈复制框需要复制，其余默认不复制，不反复增加提示标签。
5. 中文自然直接，少堆分号、缩写、空泛总结及机械小标题；不反复用“模型做了、给了、完成了”，不以“整体判定”兜底。中文与英文、数字、单位之间不人为添加无意义空格，英文词组、代码、命令、路径、引用及平台标签的必要空格保持原样。润色不得改变事实、数值、引用及证据含义。
6. 已见事实与原因推断分开表述，一次失败不能证明模型有稳定缺陷。不能用“过程是7分”解释产物分。重要发现均须实际核验并可定位，不能用局部截图推断整份文件或全部执行。

### 防止整稿套用同一句式

模板只规定栏目、编号和必需信息，不规定正文句子与给分依据的位置。先按每栏事实写出判断，再组织文字；禁止先复制上一模型的段落骨架，再替换模型名、问题和分数。给分依据可在编号评价前或后，分数可在句首、句中或句尾，不设前后位置配额，也不按模型顺序轮换句型。反馈按实际使用结果、受阻点或影响展开，仅在确有必要时给出修改建议，不把“问题＋应先做A再做B”当作必填结构。

交付前把本次所有评分稿作为一组检查，不只检查单个段落：横向阅读全部给分句和产出物反馈，比较信息顺序、开头、结尾与建议方式。若遮去模型名、分数和具体名词后，多段仍是同一句子骨架，或全稿固定末尾报分、每条反馈都追加修改步骤，应回到各栏最重要的事实重写。只换“因此／所以”、添加副词、机械前后交替或换主语，均不视为完成修订。常用词自然重复可以保留，不为了求异损害清晰度。

同时比较全部反馈的篇幅与展开程度，不能只改句式却仍然每段差不多长。整体得分较高、剩余问题少的产物，反馈简短抓住一个新发现即可；得分较低、使用障碍多的产物，应把未在前两栏展开的具体表现、使用后果和必要条件讲充分，篇幅可以明显更长。不设统一字数，不按模型次序轮换长短，也不靠空泛建议或重复扣分理由补字数。两栏得分不一致时，以实际剩余使用问题决定展开程度，不另计算总分。

这项检查必须在首次交付前完成；用户发现重复后再手改不算完成质检。检查在内部进行，不另产报告或给用户增加说明栏目；修订后核对分数、事实、标签、证据链接及截图操作没有被文风调整改变。参考稿仅用于理解证据组织，不能复制其不适用的句型。

用户提供少量喜欢与不喜欢的案例可以辅助校准语气，但不要求用户整理语料库。若采用案例，应提取其适用情境与表达原因，不建立逐段抽取或轮换套用的句型库。
