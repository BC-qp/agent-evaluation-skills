# 任务级RUBRIC编写规则

用户要求按已确认格式编写任务级RUBRIC时，使用[任务级RUBRIC模板](../assets/templates/task-rubric.txt)。先读取本次评测任务书及已确认提示词和附件；本模板不代替官方分制、表单或评分稿模板。

## 输出与验收依据
1、最终RUBRIC使用纯文本。每项严格四行：`序号、名称。`、`优秀：…`、`合格：…`、`不合格：…`。项与项之间不空行，不用Markdown标题、项目符号、表格或代码围栏。
2、三项示例只是骨架，应依任务扩展或合并，不固定条数。每项评价独立质量或有意义的跨模块结果，防止同一缺陷换名重复评价。
3、合格描述完成该项的最低实际行为；优秀强调有价值的完整性、正确性和使用质量；不合格给出关键缺口。不要用“优秀做十个、合格做五个”替代业务差别。
4、每项应有提示词或明确附件需求依据，内部覆盖表关联需求、可观察结果和核验入口。不要临时加入未告知模型的业务能力或美术偏好。
5、独立算法、实际交互、资源恢复、性能等只在任务确实需要时评分，不能每题强塞。复现与证据项评价实际可核查结果，不能只看文件存在。
6、遵守本次评测平台评分口径。没有明确要求时不自造权重或分值，不要求不同模型必须得不同分；分数相同可以成立。
7、RUBRIC由评测者使用，不作为执行模型附件，不要求模型自评。工具调用量内部单独核对，不能让模型靠循环、截图或文件数量“达标”。

## 内部覆盖检查
为每项记录对应需求、可观察结果与核验入口，检查核心需求未遗漏且无重复评价。覆盖记录留在内部，不下发给执行模型。
模板提供三项示例，不固定项目数。三维、双工程、特定任务的模块数、功能点数及工作量目标都不自动成为其他任务要求。
实际评分以当前官方规则和用户明确适用的口径为准；历史批次的分数差异限制不自动迁移。
