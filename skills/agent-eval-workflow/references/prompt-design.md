# 任务设计接口

1. 读取任务目标、允许输入、输出格式、实际评测环境与必要限制。
2. 从业务闭环写目标、必要输入、交付物、验收条件、失败处理和操作边界。不要提供标准答案、隐藏解法或逐步工具配额。
3. 需要把零散工作材料提炼成任务时，可使用独立的 `task-distiller`；输入只含中性业务材料，不传候选模型身份、分数或历史答案。没有该 Skill 时，按本文件检查输入与验收，并明确缺口。
4. 同题比较冻结相同提示词和必要输入。只有提示词和完成任务必要的脱敏附件下发，内部评分、映射和设计记录不随题下发。
5. 保留交付文件、阶段性写入和自检要求。允许合理批处理与自动化，不用工具调用数、模块数量或报告数量替代真实难点。
6. 时效性事实要区分资料支持、推断和待确认。环境禁止某类输入输出时按本次约束设计。
7. 追加需求由上游按真实轨迹和产物形成中性目标，再做任务提纯；详见[追加需求](follow-up-tasks.md)。

复杂度分析分清难度、工作量、工具调用量和完成深度。调用估计注明统计单位、共享准备、复用、批处理及待验证假设，不保证未经运行的次数下限。完整映射方法由配套任务提示词 Skill 维护。
