# 产物维度评分

先读取[评分接入](scoring-contract.md)和[证据身份](evidence-identity.md)。

按实际需求判断准确性、完整性、逻辑、指令遵循和可用性。RUBRIC用于逐项检查要求与发现缺陷，不擅自把优秀、合格、不合格换算加总成平台分数。

以下仅供采用10分制且本次评测未另定分档时校准质量程度，不是各次评测官方统一分档，也不是自动打分公式：

| 参考分段 | 产物状态 |
|---|---|
| 9至10 | 高质量、完整可用，主要要求得到充分实现 |
| 8 | 交付较好，仅有少量不影响主要使用的不足 |
| 7 | 主要目标已实现，基本可用；不足集中在局部，修订范围明确 |
| 6 | 主体成立，但有明显缺陷，需要修改 |
| 5 | 部分可用，仍是需要较多补充的半成品 |
| 4 | 核心内容或可用性不足 |
| 3 | 基本失败，只剩少量可用片段 |
| 1至2 | 几乎没有有效交付，或严重偏离任务 |

具体分数要说明缺陷影响了哪些关键目标、可用部分有多少、用户还需承担什么修改工作。同类问题也要区分严重程度，不能见到一个错误就统一给6分，也不能因篇幅长、文件多而统一给高分。

## 验收深度

从文件清点深入事实、计算、来源对应、逻辑、跨文件一致性、可运行性、视觉表现及使用体验。教程检查学习输入、操作、预期输出及验证方法；代码检查关键功能和边界；动态作品检查连续运行或视频。不要用篇幅、文件数、README承诺或PASS文本代替验收。

同题比较按[独立评分与横向校准](score-calibration.md)，标签和证据分别见[归因规则](attribution.md)与[取证规则](evidence-capture.md)。
