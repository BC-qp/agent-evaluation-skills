# 完整评测体系：从出题到报告

本体系通过两套 Skill 串联任务设计与证据评审。阶段可以单独使用，也可按完整流程执行。只创建本次需要的文件；没有来源或运行结果时保留缺口，不为了填模板编造内容。

## 一、阶段与交接

| 阶段 | 需要什么 | 做什么 | 交接结果与进入下一步的条件 |
|---|---|---|---|
| 1. 接入与出题 | 目标、授权材料、场景约束 | task-distiller分层、脱敏、校准粒度，形成可观察任务 | 提示词、必要脱敏附件、内部设计记录；关键输入足够且任务可验收 |
| 2. 冻结与RUBRIC | 已确定提示词、本次评分规则 | 固定输入版本，建立需求与验收覆盖，核对评测条件 | 输入清单、内部RUBRIC、环境约定；执行输入不含内部答案和评分材料 |
| 3. 运行与归档 | 冻结输入、实际模型与工具 | 按本次规则隔离运行，记录人工介入，先归档再清理 | 原始产物、最终答复、完整轨迹、运行记录；任务、模型、轮次能对应 |
| 4. 产物验收 | 原始产物与实际要求 | 打开、运行、复算或检查实际可用性 | 每项结论、证据位置、缺陷影响与未验证项 |
| 5. 过程评审 | 主会话、续接、子会话与运行记录 | 检查理解、实施、工具、恢复、核验、交接 | 行为事实与恢复结果；不从产物分反推过程分 |
| 6. 评分与取证 | 两维度事实、本次分制与标签 | 独立定档、必要同题比较、匹配标签、选择证据 | 评分稿、证据索引、必要截图；分数、正文、定位一致 |
| 7. 报告写作 | 已核验评分稿和证据 | 汇总适用范围、主要发现、对比、建议与限制 | 面向读者的报告；结论可追溯，不新增无来源总分或权重 |
| 8. 交付与复核 | 报告、评分稿、获准共享的材料 | 核对文件、引用、隐私、版本、提交字段 | 授权范围内的交付包；原始证据和敏感映射留在内部 |

分制、模型数、截图数量、标签、是否允许AI辅助以及提交字段，均由本次评测决定。这里没有统一强制次数、固定分差或默认排名。

## 二、建议工作目录

```text
evaluation/
  01_design_private/        设计、脱敏判断、假设和验收清单
  02_executor_input/        prompt.md与必要脱敏附件
  03_run_archive/           按task/model/run分别保存原始记录
  04_review_private/        RUBRIC、逐项验收、复核和取证索引
  05_reports/               评分稿与汇总报告
  06_delivery/              明确允许交付的文件副本
```

这只是推荐命名，已有工作区可沿用原结构。`02_executor_input/`是执行者能看到的输入边界；其余内部设计和评审目录不能一并上传给待测执行者。脚本创建的任务包是内部归档骨架，不等于可直接下发的输入包。

## 三、输入清单与冻结

使用[输入清单模板](../assets/templates/input-manifest.md)记录提示词版本、附件、模型条件、实际轮次和读取权限。对比任务冻结相同输入；若允许差异，说明比较的条件和限制。不要把追加要求混入首轮成绩。

内部可记录哈希辅助版本核对；公开报告不公布可关联私人材料的原始哈希。恢复、复制、脱敏后的文件分别标明身份，不宣称字节相同。

## 四、验收、评分与取证

[验收矩阵](../assets/templates/acceptance-matrix.md)把要求映射到可观察结果与核验方式。它记录覆盖情况，不自动产生分数。[证据索引](../assets/templates/evidence-index.md)定位每条事实，不用摘要替代原文。

评分依据完整的[产物规则](product-quality.md)与[过程规则](process-quality.md)。截图如何选择、定位和展示见[取证方法](evidence-capture.md)，禁止行为见[取证红线](evidence-redlines.md)。

## 五、报告与交付

单任务使用[评分稿模板](../assets/templates/scoring-report.md)，跨任务总结使用[评测报告模板](../assets/templates/evaluation-report.md)。报告读取已核验评分稿，不凭印象重评。报告未要求排名时不新增排名；缺可比条件时不做合并平均。

写作和证据检查在交付前完成，避免用并行“修订报告”给读者增加负担。最终说明实际完成内容、证据范围、尚未确认的限制与准确文件入口。

## 六、可直接使用的完整流程请求

```text
请用 task-distiller 和 agent-eval-workflow 完成这次评测。

先阅读提供的任务材料、评分规则和环境说明，核对目标、授权、输入与交付范围。将材料整理成脱敏任务提示词，保留业务难点、明确交付与验收，内部设计和评分资料不要交给执行者。

冻结提示词和必要附件，建立本次RUBRIC及运行清单。按已授权的模型与运行范围执行，保留真实轨迹、原始产物、最终答复及必要人工介入记录。没有运行条件时完成独立准备，明确待补条件，不伪造执行。

分别验收产物与过程，按本次分制独立评分；每条结论给出位置和任务影响，核查错误之后是否恢复。只评价约定轮次，不把工具次数或错误条数直接换算成质量分。

完成评分稿、必要证据和汇总报告。检查截图原文、复核身份、引用与隐私，交付实际要求的文件。报告说明范围与限制，不把单次任务表现扩大为模型长期能力结论。仅在本次已明确授权的目标平台提交。
```
