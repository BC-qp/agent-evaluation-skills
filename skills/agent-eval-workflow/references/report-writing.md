# 评测报告写作

报告整合已经验收的事实，帮助读者判断适用性与下一步。它不替代逐任务评分稿，也不在总结时另造分数。

## 输入

读取本次目标、实际范围、任务与模型条件、已核验评分稿、证据索引、未完成项和适用规则。仅有评分摘要时说明证据覆盖限制，不能暗示已经重看所有产物。

## 结构

使用[报告模板](../assets/templates/evaluation-report.md)，按读者和授权交付裁剪栏目：

1. 结论与适用范围：先说明本次证据支持什么，不能支持什么。
2. 任务与方法：说明输入、模型条件、轮次、评价维度和必要限制。
3. 结果：按任务与维度列出已确认结果。不同分制、不同输入或不可比条件不得直接平均。
4. 关键发现：每条包括触发条件、实际行为或产物、证据位置和使用影响。
5. 典型案例：选择能解释模式的案例，注明该结论覆盖的实际样本，不把重复描述当多个独立样本。
6. 改进建议：对应已证实的缺口，说明建议改变什么与如何复验。不把建议写成已经修复。
7. 限制：缺轨迹、无法复现、环境差异、轮次差异、材料访问限制和未执行检查。

## 汇总边界

- 只有本次明确规定的分制、总分和权重才能进入汇总。没有综合分时按维度并列，不私自计算。
- 各维度排序可以不同；证据接近时允许同分，不为讲故事强排胜负。
- “本次观察到”不等于“该模型总是”。跨任务模式要有对应的多个真实样本与范围说明。
- 原始事实、因果推断、建议和待确认事项分开。耗时与成本仅在统计口径可比时比较。
- 缺失值写未评或无法确认，不能用0暗示失败，除非本次表单明确定义该含义。

## 表达与交付检查

按[语言规范](writing-style.md)写具体事实，避免套句、空泛优缺点和重复反馈。按[取证红线](evidence-redlines.md)检查案例材料，确保报告中的分数、事实和引用与评分稿一致。

正式发布前按[隐私与提交边界](privacy-and-submission.md)处理读者权限与共享范围。内部原值映射、私有链接和原始运行标识不随公开报告外发。
