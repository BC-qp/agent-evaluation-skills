# 评分接入与规则优先级

1. 开始评分前读取本文件、[证据身份](evidence-identity.md)、对应维度的完整规则、[写作规范](writing-style.md)和[评分模板](../assets/templates/scoring-report.md)。主入口只负责路由，不能代替这些细则。
2. 本标准规定通用验收、写作与取证方法，不代替本次评测任务书、指南、实际表单和任务RUBRIC。每次评测核对官方来源、更新版本、实际输入、评测范围、分制、字段、标签、截图要求、运行环境及提交限制。通用默认与本次评测明确要求冲突时，按本次评测要求适配，并仅在确有必要时于稿首简述；不把历史评测内部公式冒充官方规定。无法消解的来源冲突须指出，不自行豁免要求。
3. 分制、模型数量、工具次数门槛、任务数量、云端或本地运行、是否需要专家亲测等都属于本次评测条件，不能从历史评测直接复制。需要专家亲测时，辅助复核和草稿不代替本人验收与确认。官方要求不能由机器人答疑或旧稿覆盖。
4. 不自行增加平台没有的维度、总分、效率分、权重或封顶。采用“产物质量、执行过程、产出物反馈”的表单时，前两栏分别评分，反馈不另给分；1—10整数分及0表示未填的约定仅在当前表单如此规定时采用。其他分制按本次评测原定义，不擅自换算。
5. 只按实际任务和RUBRIC验收，不强加题外要求。允许的模拟、公开样本复算或替代实现如实标明后按其要求检查；不能另要求付费API、生产部署或未要求的真实业务运行。题目缺输入、约束矛盾或泄露答案要辨认为任务设计问题，不能全部归罪模型。外链失效或版本变化先核对时间和原始来源，不直接判幻觉。
6. 本轮做哪些任务、几个模型、是否先做样本，由用户当前授权决定。已要求一次完成多个任务或全部模型时，不沿用历史评测“先做一个再等确认”的限制。
