# 运行与归档

## 接入信息

记录本次评测的目标、任务列表、模型列表、运行器、系统与shell、输入版本、必交材料、评分口径、运行隔离、清理规则及提交要求。版本和实际配置以本次检查为准。

建议工作区：`inputs/` 保存冻结输入，`runs/<task>/<model>/` 保存每次运行，`scoring/` 保存评分稿，`submission/` 保存用户要求的提交包。已有明确命名时沿用。

## 每个任务与模型

1. 验证当前模型及工作目录，按本次规则建立干净上下文；修改配置前保存可恢复副本。
2. 发送冻结的提示词及必要附件，记录真实开始时间与输入版本。
3. 记录必要的人工介入、错误和恢复，保存最终答复及生成文件。
4. 在清理前导出完整会话与产物，确认最后一轮、主会话、续接和子会话都能对应。
5. 按需要保存原图或连续录屏，记录模型、任务、轮次、起止及相对证据路径。
6. 只清理已授权的本轮运行目录或状态，不删除无关用户文件和全局配置。

不同运行器使用各自当前说明中的启动、会话导出和清理方式，不套用另一工具的目录与命令。配置中只归档复现必要且已脱敏的字段。

## 任务包

从 Skill 根目录运行 `python scripts/create_task_package.py <新目录>`。填写提示词、工具说明和必要环境说明，放入实际工具与输入；实际运行后才加入 `trace_*.jsonl`、最终回复和产物。

运行 `python scripts/validate_task_package.py <任务包目录> --json`。结构通过不证明工具可用、记录真实或需求完成，仍要按评分模块验收。模板不得改名冒充真实运行产物。

## 实时执行指南

实时指南按“配置与验证 → 任务 → 归档 → 检查 → 清理”的实际顺序编排。每个操作块提供当前所需提示词位置和经过核验的命令，避免来回翻页。任务块应覆盖模型与任务的实际组合；路径、模型、命令和范围逐块核对，不搬用别次评测参数。

## 交付包检查

必交文件齐全、轨迹与产物版本对应、工具可用、环境说明足够复现、证据能定位、敏感内容已处理、中文可读、压缩包可打开。是否需要压缩和外部提交以用户授权为准。
